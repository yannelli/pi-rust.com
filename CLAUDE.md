# CLAUDE.md

This file mirrors AGENTS.md.

Static Astro 7 site for pi-rust.com on a Cloudflare Worker. Read `README.md` first; the docs are listed in [docs/README.md](docs/README.md).

- **Do not edit `src/content/` or `src/data/upstream.json` by hand.** `npm run sync` writes them from yannelli/pi-rust. Fix wrong docs upstream, then sync.
- **Never state a fact the pi-rust repository does not.** Hand-written copy lives in `src/pages/index.astro`, `src/pages/install.astro`, and `src/data/faq.ts`; check each claim against the synced docs. Numbers come from `upstream.json`, not from memory.
- **Legal pages:** `src/pages/privacy.astro` and `src/pages/terms.astro` are hand-written; the operator, mailing address, phone, legal and privacy emails, site repo URL, and `TERMS_VERSION` live in `src/lib/legal.ts`. The privacy policy states what the site collects, who sees it, and how long it is kept, from the Worker code and `docs/`. When a change alters any of those (a new table or column, a retention period, an admin view, a cookie, a third party), update the page and its `EFFECTIVE` date in the same change. Sign-up stores `TERMS_VERSION` as the Terms a user accepted: change it only with new Terms text, and the Terms promise account holders an email 30 days before a material change. Both pages say pi-rust.com is directed to the United States and not to the EEA, the UK, or Switzerland; do not add EU languages, currencies, contact points, or marketing aimed there without revisiting them. See [docs/legal.md](docs/legal.md).
- **Writing:** plain words, short sentences, sentence case in site copy. No hype words ("blazing", "seamless", "powerful"), no all-caps labels, no "→" in link text. Never name another product or site as a design reference in code, comments, or docs.
- **Docs in `docs/`:** each page starts with a `#` title and a linked contents list of its `##` and `###` sections, then `## Introduction`. Headings are in title case. Keep sections short and task-based; prefer tables and code blocks to long paragraphs, and use `> [!WARNING]` or `> [!NOTE]` only for what can break something. List a new page in `docs/README.md` and the README's Documentation section.
- **Color:** the interface is monochrome. Rust, oxide, and amber mark pi-rust itself only.
- **Credit:** every page keeps the footer credit and links to ryanyannelli.com and to upstream pi. The JSON-LD `Person` `@id` must stay `https://ryanyannelli.com/#person`.
- **Astro whitespace:** a line of text that wraps onto a link, `<code>`, or `{value}` loses its space (JSX rules). End the line with `{' '}`.
- **Checks:** `npm run build` (runs `astro check`), then `npx playwright test`. After a build that adds or renames a page, run `npm run og` and commit `public/og/`.
- **Release updates are automatic.** The `Sync from pi-rust` workflow (`.github/workflows/sync.yml`, hourly) syncs, tests, commits, and deploys each new pi-rust release. Do not hand-edit synced files to "update" the site; check `/version.json` and the workflow's runs instead. Nothing runs on a developer machine.
- **Bug report endpoint:** `worker/bug-reports.ts` keeps upstream pi's `/v1/bug-reports` contract, which the pi-rust client depends on. Read [docs/bug-reports.md](docs/bug-reports.md) before you change it or its R2, email, or rate-limit bindings. The recipient address is the `BUG_REPORT_TO` secret; do not commit it.
- **Install telemetry endpoint:** `worker/install-telemetry.ts` keeps upstream pi's `GET /api/report-install?version=` request format, which the pi-rust client depends on. It stores only the version, platform, and architecture in Analytics Engine; never add the IP address or another identifier. Read [docs/install-telemetry.md](docs/install-telemetry.md) before you change it.
- **Model catalog endpoint:** `worker/model-catalog.ts` keeps upstream's catalog protocol (`/api/models/providers/<id>`, version from the `User-Agent`, `types`, ETag/Last-Modified), which the pi-rust client depends on. The data lives on the pi-rust `model-catalog` branch; never hand-edit it. Read [docs/model-catalog.md](docs/model-catalog.md) before you change it.
- **Admin area:** `worker/admin/` and `src/pages/admin/` serve `/admin/` and `/api/admin/` to admins with two-step verification only; everyone else signed in gets the 404 page. Admins never see a private share's content, and every admin change goes to the `admin_events` log. Users are counted from catalog requests as a daily salted hash of IP address, platform, and architecture (`worker/catalog-clients.ts`): never store, query, or show an IP address, and never keep a day's salt after the day. Read [docs/admin.md](docs/admin.md) before you change roles, suspension, admin actions, or what admins can see.
- **Accounts and sharing:** `worker/accounts/` and `worker/share/` keep the pi CLI contract in [docs/sharing.md](docs/sharing.md) (device grant, `pirs_` tokens, `/v1/shares` with `expires_in` and `visibility`, `PATCH /v1/shares/<id>`, `/s/<id>`), which the pi-rust client depends on. Shared sessions are never indexed: keep the `X-Robots-Tag` on every `/s/` and `/session/` response and the AI crawler `Disallow` lines in `public/robots.txt`. Read [docs/accounts.md](docs/accounts.md) before you change sign-in, sessions, the D1 schema (add a new file in `migrations/`, never edit an applied one), or the security headers. `AUTH_PEPPER`, `TOTP_ENCRYPTION_KEY`, and `GITHUB_CLIENT_SECRET` are secrets; never commit them or set `DEV_MAILBOX` in `wrangler.jsonc`.
